# Strategic Documentation Generation

## Overview

The MosAIc Planning Plugin now automatically generates strategic documentation files in markdown format alongside the MCP session data. This bridges the gap between machine-readable planning results and human-readable strategic documents.

## Problem Solved

Previously, `/plan-*` commands only stored results in JSON format within the MCP session state (`~/.mosaic/data/planning/`). While this data was accessible programmatically, stakeholders needed readable strategic documentation including:

- Executive summaries
- Business strategy documents  
- Financial projections
- Technical architecture decisions
- Market research findings
- Release roadmaps

## Solution Architecture

### DocumentationGenerationService

**Location**: `packages/planning-plugin/src/services/DocumentationGenerationService.ts`

The service integrates with:
- **StateTracker**: Accesses completed planning module data
- **ProjectDetectionService**: Determines correct documentation paths
- **File System**: Creates markdown files in project docs structure

### Integration Points

The service is integrated into:

1. **Individual Planning Commands** (e.g., `plan-business.js`)
   - Generates documentation after successful module completion
   - Creates domain-specific strategic documents

2. **Complete Pipeline** (`plan-all.js`)
   - Generates comprehensive documentation at pipeline completion
   - Creates consolidated strategic overview

## Generated Documentation Structure

```
docs/task-management/business-plan/{domain}/planning/
├── EXECUTIVE-SUMMARY.md          # High-level project overview
├── BUSINESS-STRATEGY.md           # Business analysis and strategy
├── FINANCIAL-PROJECTIONS.md      # Financial planning and projections  
├── TECHNICAL-ARCHITECTURE.md     # Technology decisions and architecture
├── MARKET-RESEARCH.md             # Market analysis and strategy
└── RELEASE-ROADMAP.md             # Release planning and timeline
```

### Domain Detection

The service automatically detects project domains:

- **From business module metadata**: `domain` field
- **From project context**: ProjectDetectionService detection
- **From project ID**: Pattern matching (e.g., "sage-phr" → "healthcare")
- **Fallback**: "enterprise" domain

### Domain Mappings

| Keywords | Domain |
|----------|--------|
| phr, health, medical | healthcare |
| fintech, payment, finance | fintech |
| ecommerce, marketplace, retail | ecommerce |
| saas | saas |
| enterprise | enterprise |

## Document Templates

Each document type uses structured markdown templates with:

- **Header**: Generation timestamp, session info
- **Content Sections**: Extracted from planning module outputs
- **Metadata Tables**: Key planning decisions and parameters
- **Footer**: Generated by MosAIc branding

### Template Variables

Templates use planning data variables:
- `projectId`: Project identifier
- `businessResults[]`: Business planning outputs
- `financialResults[]`: Financial planning outputs  
- `techResults[]`: Technical planning outputs
- `metadata{}`: Planning module metadata
- `createdAt`: Planning completion timestamp

## Configuration Options

### DocumentationGenerationService Config

```typescript
interface DocumentGenerationConfig {
  outputDir?: string;     // Override default output directory
  projectId?: string;     // Override project ID detection
  templateDir?: string;   // Custom template directory
}
```

### Project Detection Override

```typescript
// Custom output directory
const docService = new DocumentationGenerationService(stateTracker, {
  outputDir: '/custom/docs/path',
  projectId: 'custom-project'
});
```

## File Generation Logic

### Document Generation Rules

1. **Executive Summary**: Generated when business module is completed
2. **Business Strategy**: Generated when business module is completed  
3. **Financial Projections**: Generated when financial module is completed
4. **Technical Architecture**: Generated when tech module is completed
5. **Market Research**: Generated when marketing module is completed
6. **Release Roadmap**: Generated when release module is completed

### Error Handling

- **Partial Generation**: Some documents generated, others failed
- **Complete Failure**: No documents generated due to system errors
- **Missing Modules**: Documents skipped for incomplete planning modules
- **Fallback Content**: Basic templates used when detailed data unavailable

## Technical Implementation

### Key Classes

```typescript
// Main service class
class DocumentationGenerationService {
  constructor(stateTracker: StateTracker, config?: DocumentGenerationConfig)
  async generateDocumentation(): Promise<GenerationResult>
}

// Result interface
interface GenerationResult {
  success: boolean;
  generatedFiles: string[];
  errors: string[];
}
```

### Integration Pattern

```javascript
// In planning command
const docService = new DocumentationGenerationService(this.stateTracker);
const result = await docService.generateDocumentation();

if (result.success) {
  console.log('✅ Documentation generated:', result.generatedFiles);
} else {
  console.log('⚠️ Documentation errors:', result.errors);
}
```

## Troubleshooting

### Common Issues

1. **No Documentation Generated**
   - Verify planning modules completed successfully
   - Check StateTracker session data exists
   - Ensure output directory is writable

2. **Partial Documentation**
   - Review error messages for specific failures
   - Check individual module completion status
   - Verify template rendering data availability

3. **Wrong Output Directory**
   - Confirm project detection is working correctly
   - Override with explicit outputDir configuration
   - Check file system permissions

### Debug Commands

```bash
# Check session status
node packages/planning-plugin/src/utils/doc-generation-cli.js --project=PROJECT --verbose

# Force generation with incomplete data

# Manual generation with custom settings

  outputDir: './debug-docs',
  projectId: 'debug-project'
});
```
